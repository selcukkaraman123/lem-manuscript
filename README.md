# LEM — Layered Executable Manuscript

**A publication architecture that makes AI's role in research auditable, from data analysis to theory building and drafting.**

Prof. Dr. Selçuk Karaman, Ankara Hacı Bayram Veli University.

Research artifact accompanying a proposal to the *Organization Science* special issue "AI-Assisted Frontiers in Organizational Science". Status: **proof of concept (v0.1)**. See [STATUS.md](STATUS.md) for what works and what is planned.

## The idea in one table

| Layer | What it holds | Status in the record | How it is validated |
| --- | --- | --- | --- |
| **H — Human** | Claims, theory, interpretation, decisions to accept or override model output | Fixed, citable, peer-reviewed | Is the argument sound? |
| **P — Process** | *Analytic* steps (prompts, model, parameters, hashed outputs) and *cognitive* steps (ideation, synthesis, drafting) with an override log | Fixed, versioned, hash-chained | Analytic: re-execution. Cognitive: traceability of each H claim to its origin |
| **R — Reader** | Summaries, translations, explanations generated by readers' own AI tools | Not part of the record | Claim Drift Index (CDI) against H |

**Two-tier logging.** Substantive cognitive steps (ideation, synthesis, drafting) are logged in full with an override log. Surface edits (spelling, grammar, tone) are logged as a meta-tag only, but are escalated automatically if they change what the text claims, for example "may suggest" → "demonstrates".

**Conformance levels.**

| Level | Scope | Assurance |
| --- | --- | --- |
| LEM-0 — Analytic Provenance | Analytic steps only | Re-execution |
| LEM-1 — Cognitive Provenance | + ideation, theory building, synthesis, drafting | Records assembled by authors |
| LEM-2 — Attested Provenance | Same as LEM-1 | Records captured live by an instrumented environment and sealed in a hash chain |

## The reference manuscript is the proposal itself

[`examples/proposal/`](examples/proposal) documents **this proposal in its own format, at LEM-1**. It was written in one session by a human author working with Claude (Anthropic). The P layer records what the model proposed and what the author accepted, rejected or rewrote. The claim index (`claims.json`) marks the origin of each anchored claim as `author`, `model` or `co-constructed`.

```
python -m lem provenance examples/proposal
```

reports the resulting division of labor (see [`reports/provenance_proposal.json`](reports/provenance_proposal.json)). One superseded draft was not archived; the record says so with a visible redaction rather than hiding the gap — exactly the weakness LEM-2 removes.

[`examples/toy-analytic/`](examples/toy-analytic) shows the **LEM-2 mechanism**: six analytic steps captured live by the capture logger and re-executable from their sealed records.

## Quick start (no GPU, no API key, about a minute)

```bash
git clone https://github.com/selcukkaraman123/lem-manuscript && cd lem-manuscript
pip install -r requirements.txt

python -m lem validate examples/proposal          # schema, hash chain, H integrity, anchors, level rules
python -m lem verify-chain examples/proposal      # tamper check only
python -m lem reexecute examples/toy-analytic     # re-run analytic steps (mock backend)
python -m lem cdi examples/proposal examples/proposal/R/summary_drifted.md   # drift of an AI summary
python -m lem surface-check "may suggest X" "demonstrates X"                 # escalation rule
python -m pytest -q                               # 11 tests
```

To re-execute with a real open-weight model, install [Ollama](https://ollama.com) and run:

```bash
ollama pull llama3.2:1b
python -m lem reexecute examples/toy-analytic --backend ollama:llama3.2:1b
```

Pre-computed outputs of every command are in [`reports/`](reports), so results can be inspected without running anything.

## Repository layout

```
schema/lem-v0.1.schema.json   JSON Schema: manifest, claim index, P_analytic, P_ideation, P_drafting, P_surface
lem/                          toolkit: hashing, capture (LEM-2 logger), validate, reexecute, claims (CDI, delta), provenance, CLI
examples/proposal/            H.md, claims.json, P/ (hash-chained records), R/ (demo reader renderings), manifest.json
examples/toy-analytic/        LEM-2 mechanism demo with live-captured analytic steps
reports/                      pre-computed outputs
scripts/                      build_examples.py, make_reports.py
tests/                        pytest suite
```
